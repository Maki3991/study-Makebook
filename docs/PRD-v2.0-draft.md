# 01 产品定义（重写）

## 1.1 MAKEBOOK 是什么

MAKEBOOK 是一个**实体商品的预售交易平台**。它服务的主体业务是预售：需求发现（评论与访谈 → 可制造 SKU）、价格发现（消费者愿付价 × 工厂成本曲线）、订单聚合（全额担保的条件订单）、生产触发（MOQ 达标才成批）、履约交付（链下，由责任方承担）。

区块链在其中只承担一件事：**让截止后的规则与资金不可被任何一方修改**。MAKEBOOK 首先是一个预售平台，其次才是一个链上项目。

## 1.2 为什么需要链：从防守到进攻（核心论证）

预售场景中有三方同时承担风险且互不信任：

| 方 | 先付出 | 承担的风险 |
|---|---|---|
| 消费者 | 先付款 | 拿不到货 |
| 工厂 | 备料开工 | 订单为假、客户消失 |
| 品牌方 | 下采购单、投入设计 | 消费者反悔、库存积压 |

传统解法是由平台居中担保，三方都信任平台。但这要求平台具备牌照、资本、历史信誉和风控能力——**因此预售基础设施在事实上只有大型平台能够运营**：

- 中国产品众筹 2015 年京东 + 淘宝两家合计占七至八成市场份额；京东、淘宝、苏宁三大平台支持人次合计占全行业 93.1%；2017 上半年权益型众筹 Top10 平台融资额占 94.57% [来源：财新 2016-02-24；北京日报 2022-10-11；界面新闻 2017-07-30]。
- 中小平台无法建立信任：2015 年一年内 40 家众筹平台倒闭、26 家转型，原因多为"规模小，无法与大平台竞争"；截至 2016 年末 608 家平台中 45% 为问题或已转型平台 [来源：财新 2016-02-24、2017-02-22]。
- 即使是大平台，信任也在流失：京东众筹（总筹资超 24 亿元，曾为国内最大）于 2022 年 10 月暂停运营；百度众筹、苏宁私募股权、蚂蚁达客此前已相继下线 [来源：动点科技 2022-10-12]。
- 社区团购先驱 Drop（原 Massdrop）的独立商城于 2026 年 3 月 31 日关闭——模式被验证，死于中心化运营的信任与成本天花板 [来源：ecoustics 2026-03-31]。

当规则与资金由公开合约执行时，信任的来源从**"平台的资本与信誉"**转移到**"规则本身的不可篡改"**。这意味着：

> **运营一个可信的预售市场，不再需要先成为一家可信的大公司。**

这是一个商业结构的改变，不是技术优化。它降低的不是交易成本，而是**进入预售基础设施行业的门槛**。由此可能出现的市场形态：垂直品类的小型预售市场——摄影器材、机械键盘、独立香水、小众服饰——每个由真正懂该品类的小团队运营。这些团队今天有品类洞察和供应链资源，唯独没有让陌生人先付款的信任凭证；MAKEBOOK 把这张凭证变成公共品。

**诚实边界（与 v1.0 一致）**：链不解决物流、质量、法律履约，这些仍需链下机制（见第 20 章履约责任边界）；P0 仅在测试网，不涉及真实资金。

## 1.3 它解决什么问题（沿用 v1.0 的断裂分析，结论更新）

v1.0 识别了四方断裂（点赞不等于购买、品牌不知哪个规格能成团、工厂不知询价是否真实、平台不把愿付价与 MOQ 做统一清算）。v2.0 补充第五条断裂：**中小团队无法获得预售基础设施**——他们要么接受大平台 8–12% 的综合费率与流量分配逻辑（Kickstarter 5% + 支付处理 3–5% [来源：Kickstarter 官方费率页]；Crowd Supply 全服务约 12% + 每件固定费 [来源：Crowd Supply Apply 页 / 创作者实测]），要么放弃预售。

## 1.4 明确不是什么（沿用 v1.0，新增一条）

沿用：不是股权众筹/投资产品/收益权/预测市场；不是 NFT 图片；不是 Injective 交易所前端；不是"AI 自动开公司"；不是对真实履约的链上保证。
新增：**不是大平台流量分发逻辑的替代品**——MAKEBOOK 不承诺流量，它把"可信清算"变成任何垂直团队可自有的基础设施；流量仍属于主理人自己的社群。

# 03 角色、权限与需求（重写品牌方部分）

## 3.1 品牌方是交易对手方（merchant of record）

**消费者向品牌方购买，品牌方向工厂采购。** 工厂是品牌方的供应商，不直接面对消费者。

| 角色 | 商业身份 | 承担 | 获得 |
|---|---|---|---|
| **品牌方（主理人）** | merchant of record | 商品责任、质保、退换货、配送、社群运营、SKU 策展 | 零售差价（清算零售价 − 出厂价 − 平台费），仅成功清算时落袋 |
| **工厂** | 品牌方的供应商 | 冻结 MOQ 出厂报价、按单生产 | 出厂价应收，清算即锁定，无账期无跑单 |
| **平台** | 清算基础设施 | 编译工具、合约、审核、风控 | 成功清算费（冻结费率 + 硬上限），失败零收费 |
| **消费者** | 买家 | 全额预锁最高愿付价 | 不高出声明价的统一零售价、失败/落选全额退 |

权限矩阵沿用 v1.0 第 3.2 节（P0 合约层面 operator 无资金权限，INV-06）。V1 合约层面新增：`creator` 地址作为品牌应收的唯一领取方——**品牌方的收入与其身份一起在开盘前冻结，平台同样不能截留**。

## 3.2 主理人角色的未来拆分（V2 方向，详见第 20 章）

设计主理人（创意 + 版税）与运营主理人（推进 + 佣金、不碰钱、成功才赚钱）可在 V2 拆分；P0/V1 由同一主体兼任。AI 压缩主理人的"调研与设计执行"，无法替代其"召集需求、法律对手方、名声担保"三重身份——后者恰是零售溢价的来源。

# 04 完整产品故事（资金流更新，过程沿用 v1.0）

前 7 步（收集 → 编译 → 确认 → 报价 → 下单 → 观察 → 截止）与 v1.0 一致。资金流结果更新为：

| 阶段 | P0（已实现） | V1（设计） |
|---|---|---|
| 定价 | 清算价 = 中标工厂档位出厂价（费率 0、无保留价） | 清算价 = 零售价（出厂价 × 冻结加价系数 + 固定履约成本），且不低于冻结保留价 |
| 成功分账 | 工厂应收 = winnerCount × 出厂价（一笔） | 三笔：工厂出厂应收 / 品牌零售差价应收 / 平台费应收，均 pull 领取 |
| 消费者 | 差额 = maxPrice − 清算价；落选/失败全额退 | 差额 = maxPrice − 零售清算价；落选/失败全额退（不变） |
| 放款节奏 | 中标工厂一次性领取（testnet，无真实履约风险） | V2：里程碑分期释放（见 20.6） |

# 07 Campaign 参数（P1/V2 新增字段）

P0 参数（manifestHash / manifestURI / operator / deadline / paymentAsset / limits）不变。以下**开盘前冻结**参数分两步落地——P1（2026-07-25 已上链）与 V2（未实现）：

| 字段 | 类型 | 作用 | 约束 |
|---|---|---|---|
| **creator** | address | 品牌应收唯一领取方 | 部署后不可改 · **P1 已实现** |
| **feeRecipient** | address | 平台费唯一领取方（≠ operator，守 INV-06） | 部署后不可改 · **P1 已实现** |
| **marginBps** | uint32 | 加价系数（基点，2500 = ×1.25） | 硬上限 ≤ 5000，constructor 冻结 · **P1 已实现** |
| **feeBps** | uint32 | 平台费率（200 = 2%），失败不收费 | ≤ marginBps（InvalidFeeConfig）· **P1 已实现** |
| **fixedCostWei** | uint256 | 固定履约成本（物流+包装+仓储履约+支付/退货准备的折算定额） | **V2，P1 未实现** |
| **reservePriceWei** | uint256 | 品牌保留价：最低可接受零售清算价 | **V2，P1 未实现** |
| **feeCapWei** | uint256 | 平台费累计硬上限 | **V2，P1 未实现** |

# 09 确定性清算规则（双层）

## 9.A P0 算法（历史口径，2026-07-25 起由 P1 取代）

与 v1.0 R-01~R-10 逐字一致，链上证据：success `0xBcA0…00c5`（Open，5 单 2 报价）、failure `0x4415…4e6d`（Open，2 单 2 报价）。清算价 = 中标工厂档位价；无保留价；平台费 0；单一工厂应收。73 个测试（CT-01~CT-12，含 P1 三方分账 22 例）与 Slither 静态分析已归档。

**P1 已实现三方分账（2026-07-25）**：算法见 9.B。P0 双批次到期后由 P1 三批次（success / failure / bracelet）取代；本节保留为历史口径，不得改述。

## 9.B P1 算法（2026-07-25 已实现）与 V2 扩展（未实现）

设工厂档位出厂价 `tierPrice`，冻结参数如上。

- **R-V1-01（零售价构造）**：每个档位的零售档位价 `retailTierPrice = tierPrice × (1 + marginBps/10000)`（floor 取整）。**P1 按此实现**；V2 扩展为 `+ fixedCostWei`（整数除法余数归入平台费，上限 feeCapWei 覆盖）。
- **R-V1-02**：eligibleCount = maxPrice ≥ retailTierPrice 的订单数（量纲统一：消费者的零售支付意愿对零售档位价）。
- **R-V1-03~05**：可行性与选择与 P0 相同（eligibleCount ≥ minQty → 可行；先数量后价格再 quoteId/tierIndex）。
- **R-V1-06（保留价）**（**V2，P1 未实现**）：选定中标档位后，若 `retailTierPrice < reservePriceWei`，该档位判不可行；无任何同时通过 MOQ 与保留价的档位则 state = Failed，全员全额退款。
- **R-V1-07（分账）**：clearingRetailPrice = 中标零售档位价；factoryReceivable = winnerCount × tierPrice；platformFeeTotal = winnerCount × clearingRetailPrice × feeBps/10000（合约内与 marginPool 取 min 兜底，永不下溢）；creatorReceivable = winnerCount × (clearingRetailPrice − tierPrice) − platformFeeTotal；买家差额 = maxPrice − clearingRetailPrice。工厂/品牌/平台/买家四类均 pull 领取，互不阻塞。**P1 按此实现**（V2 再加 feeCapWei 上限）。

**保留价手算示例**：随 V2 实现补充；附录 A2 已重写为 P1 口径（与 testnet 链上数字逐 wei 一致）。

## 9.C 为什么不用更简单的做法

- **为什么保留价不直接等价为调高 MOQ？** MOQ 是工厂的产能约束，保留价是品牌的盈利约束，两者来源不同：工厂报价冻结后品牌无法通过 MOQ 表达"低于此价不做"。合并会迫使品牌虚报 MOQ，破坏工厂报价的真实性。
- **为什么加价公式上链而不是后端计算？** 后端可改。公式冻结才能让消费者在下单前看到每一分钱的分配，并把"价格透明"从 Everlane 式品牌自律（公开成本但自行定价 [来源：HBS Everlane 案例 2015]）升级为规则强制——**Everlane 告诉你成本是多少，MAKEBOOK 让任何人都改不了这个数**。

## 19.2 评委问答新增

**Q：品牌方怎么赚钱？**
零售差价：品牌应收 = winnerCount ×（零售清算价 − 出厂价 − 平台费），由冻结公式分配。清算价的含义是**市场发现的品牌溢价**——Everlane 式成本透明 + Gustin 式工厂直价 + 资金曲线定价。

**Q：清算价和工厂价混用，量纲不是错了吗？**
v1.0 确实错配（零售意愿对出厂报价）；v2.0 的零售价构造（出厂价 × 冻结系数 + 固定履约成本）让比较发生在同一量纲（9.B R-V1-02）。

**Q：消费者会不会被加价公式收割？**
系数开盘前冻结并公开，下单前可见每一分钱分配；预售模式无库存风险（传统品牌未售库存约 30% [来源：SHEIN 模式报道]）、无平台流量 CAC（DTC CAC 三年上涨 40–60% [来源：Eightx 2026；Digital Applied 2026]）、需求前置——可接受显著低于传统 DTC（3–5x COGS [来源：Eightx/JOOR 口径]）的加价倍率，论证见 20.3。

**Q：为什么上链？（进攻型标准回答）**
见第 1.2 节。一句话：预售基础设施今天只有大平台能运营，因为信任需要资本与牌照；当规则与资金由公开合约执行，信任的来源变成规则本身——运营可信预售市场不再需要先成为可信的大公司。这是商业结构的改变。

# 20 商业模式与产品路线图（重写 20.1，新增 20.5–20.8）

## 20.1 谁会付钱（重写，含单位经济模型）

平台收入只来自成功清算费（失败零收费）。费率对标：Kickstarter 综合 8–10%（5% 平台 + 3–5% 支付）[来源：Kickstarter 官方费率页]；Crowd Supply 全服务约 12% + 每件固定费 [来源：Crowd Supply Apply / 创作者实测 2022]；MAKEBOOK 早期 1%–3%——低于行业一半以上，因为 P0/V1 不提供履约服务，服务范围决定费率水位。

**单笔 Campaign 平台收入测算（FRAME-01 例）**：零售清算价 ¥333.75、成交 65 件 → GMV = ¥21,694；2% 费率 → 平台收入 ¥434；3% → ¥651。

**平台成本结构**：合约 gas（Injective 单笔约 $0.0003，可忽略 [来源：Injective 官方资料]）；AI 推理（每 Campaign 约 ¥0.1–1，视模型）；审核与客服人力（主成本，小团队约 ¥30,000–50,000/月）；风控（KYB 抽查）。

**盈亏平衡**：月收入 = 成功 Campaign 数 × 平均 GMV × 费率。设平均 GMV ¥20,000、费率 2%：每单 ¥400；覆盖 ¥40,000/月成本需 **100 个成功 Campaign/月**。杠杆：费率至 3%（仍低于行业一半）→ 67 个；平均 GMV 至 ¥50,000（更高客单品类）→ 27–40 个；白标 SaaS（固定月费 + 低费率）平滑波动。结论诚实写明：**清算费模式需要规模，早期收入补充是白标与工厂侧 SaaS**（V3 路线图）。

## 20.2 主理人怎么赚钱（零售差价模型）

品牌应收 = winnerCount ×（零售清算价 − 出厂价）− 平台费（P1 已上链，2026-07-25）。FRAME-01 testnet 分账手算见附录 A2。

## 20.3 公开冻结加价公式与合理区间

公式：`零售价 = 出厂价 × 加价系数 + 固定履约成本`，开盘前冻结并公开（修订 3）。加价系数合理区间的论证：

- 传统零售倍率：keystone 2x 落地成本（批发惯例）；DTC 3–5x COGS（自担 CAC/退货/履约）[来源：Eightx 2026 引用 JOOR/Bond Street]；Everlane 约 2–3x vs 行业 5–6x/8x [来源：HBS 案例 2015；RetailWire 2016]。
- 预售的结构性优势：无未售库存（行业均值约 30% 库存积压 [来源：SHEIN 模式报道，媒体口径]）；需求前置 + 社群自带流量，近乎零 CAC（对照 DTC CAC 三年 +40–60%）；无滞销降价损失。
- 据此预售加价系数 **1.2–1.8x** 是可辩护区间（标注：论证性估算，需真实 Campaign 数据校准）；Gustin 的 $81 vs $205（约 2.5x 零售/出厂比 [来源：Worn & Wound 2014]）验证了工厂直价模式在 1.5–2.5x 区间的市场接受度。

## 20.4 品牌保留价（修订 4）

机制见 9.B R-V1-06。保留价保护品牌免于"达到 MOQ 但清算价跌破盈利线"的强制成交；它开盘前冻结并公开，消费者下单前即知底价存在（具体数值可只哈希上链、清算时揭示——V1 的可选隐私变体）。

## 20.5 清算分账规则（修订 5）

见 9.B R-V1-07。P0 简化实现（单一工厂应收、费率 0、无保留价）已在链上运行；V1 实现完整三账。

## 20.6 分期释放机制（V2 设计，P0/V1 不实现）

一次性放款无法解决预售最大风险（收款后不交付；Kickstarter 成功项目约 9% 未交付、75% 延期 [来源：Kickstarter Fulfillment Report 2015；Mollick 2014]）。V2 设计：

| 阶段 | 释放 | 凭证 | 上链验证？ |
|---|---|---|---|
| 清算成功 | 工厂启动定金 30% | 无需（清算事件） | 是 |
| 发货 | 工厂尾款 60%（出厂部分） | 物流单号哈希 + 承运商回执 | 单号哈希可上链；真实性靠承运商/品牌确认（链下可信方） |
| 收货确认期结束（如 7 天） | 工厂质保金 10% + 品牌毛利全额 | 确认期无争议自动放行 | 时间锁链上执行；争议判定靠链下 |
| 异常 | 逾期未交付：未释放部分按买家比例退回；部分交付：按交付比例结算；质量争议：仲裁多签冻结 | 争议规则开盘前冻结 | 执行在链上，认定在链下 |

依据：30% 启动定金对应工厂备料资金需求（行业惯例估算，待真实工厂访谈校准）；Indiegogo 创作者条款已允许平台在履约风险情形暂扣/分期释放资金 [来源：Indiegogo Creator Guidelines 2026]——分期释放是行业对"托管真实性"的共同答案。**托管只有与释放规则结合才有真实意义**：钱在合约里不等于安全，按物理世界进展释放才是。

## 20.7 履约责任边界（修订 8）

| 责任 | 承担方 | 阶段 | 机制 |
|---|---|---|---|
| 商品质量 | 品牌方（merchant of record） | 全周期 | 工厂 KYB + 质检报告 + 保留价/保证金 |
| 交期 | 品牌方 + 工厂 | 生产期 | 里程碑放款 + 逾期退款规则（20.6） |
| 物流 | 品牌方 | 交付期 | 单号哈希 + 承运商回执 |
| 退换货 | 品牌方 | 售后 | 退换准备金（计入固定履约成本） |
| 消费者权益 | 品牌方为主、平台为辅 | 全周期 | 争议流程 + 平台下架权 |
| 资金规则 | 合约 | 清算期 | 冻结参数 + pull 支付 |

声明（沿用 v1.0 16.1）：合约不保证真实制造、物流与法律履约；生产版本需要 KYB、保证金、质检、争议流程硬门槛。

## 20.8 路线图（在 v1.0 20.2 基础上修订）

- **MVP / P0（已完成）**：单 SKU、统一出厂价清算、单一工厂应收、testnet 双 Campaign 证据。

# 附录 A2｜P1 价格结构与分账手算示例（2026-07-25 与链上一致）

FRAME-01 testnet success 批次真实参数：报价 North MOQ 3 @ 出厂 0.024 / Loom MOQ 3 @ 出厂 0.019（testINJ）；冻结参数 marginBps = 2500（×1.25）、feeBps = 200（2%）。

**零售档位价**：North 0.024 × 1.25 = **0.030**；Loom 0.019 × 1.25 = **0.02375**。

**需求**：5 笔全额预锁订单，愿付价 0.034 / 0.032 / 0.028 / 0.026 / 0.022。

| 候选档位 | retailTierPrice | eligibleCount | MOQ | 结果 |
|---|---|---|---|---|
| North / 3 @ EXW 0.024 | 0.030 | 2（0.034、0.032） | 2 < 3 不可行 | 淘汰 |
| Loom / 3 @ EXW 0.019 | 0.02375 | 4（≥ 0.02375） | 4 ≥ 3 可行 | **中标** |

清算：4 名赢家各付统一价 0.02375；末单 0.022 落选，全额退 0.022。

**三笔分账（逐 wei 可手算复现）**：

- 工厂应收 = 4 × 0.019 = **0.076**
- 平台费 = 4 × 0.02375 × 2% = **0.0019**
- 品牌应收 = 4 × (0.02375 − 0.019) − 0.0019 = 0.019 − 0.0019 = **0.0171**
- 买家差额 = maxPrice − 0.02375（如 0.034 → 退 0.01025）

托管守恒校验：0.076 + 0.0171 + 0.0019 = 0.095 = 4 × 0.02375。✓

**V2 完整形态（未实现）**：加入 fixedCostWei / reservePriceWei / feeCapWei 后公式扩展为 `retail = tierPrice × (1 + marginBps/10000) + fixedCostWei`，保留价可判失败、平台费设累计上限；¥ 计价的保留价手算例随 V2 实现一并恢复。
